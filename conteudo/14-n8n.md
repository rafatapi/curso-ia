## Um processo desenhado em etapas
No n8n, um workflow conecta nós que recebem e produzem dados. Um gatilho inicia a execução. Nós seguintes transformam, consultam ou encaminham os itens. Você pode inspecionar a entrada e a saída de cada etapa para descobrir onde uma informação mudou.

Para praticar, use uma instância de teste no serviço hospedado ou uma instalação local. O serviço hospedado pode ter cobrança e condições de teste; confira no fornecedor. A instalação local exige manutenção e não se torna um serviço de produção apenas por funcionar no computador.

## Opção local com Docker
Instale o Docker pela fonte oficial e confirme que ele está em execução. O exemplo cria um volume persistente e publica a porta apenas no endereço local do computador. Confira no guia oficial a versão estável que deseja utilizar; para estudo, o comando abaixo usa a imagem estável 2.39.7 indicada na documentação consultada. É uma instalação mínima de laboratório; para operação durável, siga o guia atual de Docker Compose do fornecedor.

```powershell
docker volume create curso_ia_n8n
docker run -d --name curso-ia-n8n -p 127.0.0.1:5678:5678 -e GENERIC_TIMEZONE=America/Sao_Paulo -e TZ=America/Sao_Paulo -v curso_ia_n8n:/home/node/.n8n n8nio/n8n:2.39.7
```

1. Abra `http://localhost:5678` no navegador.
2. Conclua a configuração inicial da conta local.
3. Crie um workflow vazio e localize a área de nós e o histórico de execuções.
4. Registre a versão do n8n usada no laboratório.
5. Para parar, use `docker stop curso-ia-n8n`. Para iniciar novamente, use `docker start curso-ia-n8n`.

O volume guarda os dados da instância. Não o remova para “reiniciar” sem entender que isso pode apagar sua configuração. Se o nome do container já existir, use o container existente; não execute novamente o comando de criação às cegas.

## Faça um mapa da interface
Identifique gatilho, configurações do nó, entrada, saída e execução. Nomes de botões podem mudar entre versões, mas esses conceitos permanecem. Antes de conectar serviços reais, pratique com o gatilho manual e dados fictícios. Assim, você aprende o fluxo sem enviar mensagens ou modificar sistemas externos.

## Comece sem IA
Baixe [n8n-triagem-regras.json](downloads/n8n-triagem-regras.json). Ele contém um workflow de estudo com gatilho manual, três solicitações fictícias, classificação por palavras e separação entre itens classificados e itens para revisão. Não usa credenciais nem faz chamadas externas.

No n8n, crie ou abra um workflow de teste e use a opção de importar de arquivo no menu do editor. Se a versão pedir adaptação de algum nó, confira o tipo e suas propriedades antes de executar. O arquivo é um ponto de partida editável, não uma integração já conectada a seus serviços.

## Execute de trás para frente com os olhos
1. Execute o workflow manualmente.
2. Abra “Pedidos de exemplo” e confira os ids A1, A2 e A3.
3. Abra “Classificar por regras” e observe as categorias: financeiro, acesso e revisao.
4. Confira o nó de condição e as saídas para revisão e classificação.
5. Abra o nó final de cada caminho e confira o estado atribuído.
6. Altere o texto de A3 e execute novamente.

No nó Code, os itens aparecem em estruturas que contêm `json`. Em modo de todos os itens, `$input.all()` retorna a coleção. O trecho abaixo preserva os campos e acrescenta uma versão normalizada do texto:

```javascript
return $input.all().map(item => ({
  json: {
    ...item.json,
    texto_normalizado: String(item.json.mensagem ?? '').trim().toLowerCase()
  }
}));
```

## Leia expressões com calma
Uma expressão como `{{ $json.categoria }}` consulta um campo do item atual. O campo precisa existir na entrada desse nó. Se você renomear a chave no nó anterior, a expressão deixa de apontar para o dado esperado. Observe sempre a entrada real antes de editar uma expressão.

O classificador por palavras é propositalmente simples. “Não tenho problema de boleto, meu login falhou” pode confundi-lo. Esse limite ajuda a entender onde IA pode ser útil, mas primeiro precisamos de um caminho explícito para ambiguidades.

## Teste e produção são caminhos distintos
Um Webhook é um endereço HTTP que recebe eventos. No n8n, há um endereço de teste e um de produção conforme o ciclo de vida do workflow. Use o endereço mostrado pela sua instância; não copie uma URL de outro ambiente. A URL de teste precisa estar em modo de escuta; a de produção depende de o workflow estar publicado ou ativo conforme a versão.

## Construa um recebimento local
1. Duplique seu workflow de estudo para preservar a versão manual.
2. Adicione um Webhook com método POST e um caminho como `curso-triagem`.
3. Selecione a escuta de teste e copie a URL exibida.
4. Em um cliente HTTP ou terminal, envie um objeto com id e mensagem fictícios.
5. Inspecione a saída do Webhook. O corpo normalmente estará em um campo como `body`; confirme na sua execução.
6. Normalize para o mesmo formato que o classificador já espera.

```powershell
$urlTeste = Read-Host "URL de teste copiada do seu Webhook local"
$corpoTeste = @{ id = "W1"; mensagem = "Esqueci minha senha" } | ConvertTo-Json
Invoke-RestMethod -Uri $urlTeste -Method Post -ContentType "application/json" -Body $corpoTeste
```

## Valide antes de continuar
Exija id e mensagem, limite o tamanho e rejeite tipos inesperados. Para a prática local, não exponha o endpoint na internet. Em um ambiente real, configure autenticação, limites e verificação do emissor conforme a integração. Uma URL difícil de adivinhar não substitui esses controles.

Defina como o pedido será respondido: imediatamente com confirmação de recebimento ou após o processamento. Para tarefas demoradas, costuma ser melhor retornar um identificador e processar em segundo plano. A configuração de resposta precisa ser consistente com os nós de resposta utilizados.

## Planeje reexecuções
O mesmo evento pode chegar mais de uma vez. Guarde uma chave de idempotência em armazenamento durável antes de efeitos externos, com controle de concorrência. Um campo no JSON de uma única execução não impede duplicidade entre execuções.

Para falhas, registre etapa, id e erro sanitizado. Use um caminho de erro e uma fila de revisão. Não configure “continuar em caso de erro” sem decidir o que a etapa seguinte fará com a falha.

@answer

Registre a incerteza e encaminhe para reconciliação.
